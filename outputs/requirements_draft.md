# **3. 背景・目的**

## 3.1 背景

東亜セキュリティーズ様のリテール営業部門では、NISA改正による個人投資家の急増と競合激化、金融商品取引法改正による説明責任の厳格化といった経営環境の変化に直面されています。この変化の中で、リテール営業担当者の提案品質が競争力の源泉として重要性を増す一方、以下の課題が顕在化しています：

### 提案業務における主な課題

1. **時間負荷**: 1案件あたり情報検索に30〜60分、資料作成に1〜2時間を要している
2. **心理負荷**: 若手営業担当者は市況解釈や商品選定に自信が持てず、判断に迷っている
3. **属人性**: ベテランと若手で提案品質にばらつきがあり、ノウハウが属人化している

詳細な背景については、提案書「4. 課題認識」をご参照ください。

## 3.2 システム化（AI活用）の目的

本プロジェクトの目的は、AI Workforce導入により、リテール営業部門の提案業務における**品質と生産性を向上**させることです。

具体的には：

- **提案業務の時間短縮**: 情報検索30〜60分→10分以内、資料作成1〜2時間→30分以内
- **提案品質の底上げ**: 若手でも一定水準の提案が可能に（上長評価5段階で平均3.2→4.0以上）
- **属人性の解消**: ノウハウの組織的共有により、組織全体の提案力を強化

## 3.3 適用範囲

### Phase 1（PoC）の対象範囲

**対象期間**: 2026年2月上旬～3月末（2ヶ月）

**対象部門**: リテール営業部門、営業企画部門

**対象プロセス**:
1. 情報検索（最重要）
2. 市況整理
3. 提案資料作成

**対象ユーザー**: PoC参加メンバー6名（若手営業3名、ベテラン営業1名、営業企画2名）

### スコープ外（Phase 2以降で検討）

- 商品選定支援
- レビュー支援

### UC-01: 富裕層向けポートフォリオ提案

**目的・背景**:
富裕層顧客（資産5,000万円以上）に対し、市況変動の中で安定配当と成長株のバランスを提案する。過去の類似顧客への提案事例を活用し、品質の高い提案を効率的に作成する。

**業務フロー（Before / After）**:

**Before（現状）**:
1. CRMで顧客情報確認（10分）
2. 類似顧客の過去提案を支店ローカルから手動検索（30分）
3. 市況レポートを10本以上読み込み、要点を手書きでメモ（60分）
4. 商品DBから候補商品を検索（20分）
5. PowerPointで提案資料を作成（120分）
6. 上長レビュー・修正（30分）
**合計: 4.5時間**

**After（AI導入後）**:
1. CRMで顧客情報確認（10分）
2. AI統合検索で類似顧客の過去提案を自動検索（5分）
3. AI要約で市況レポートの要点を自動抽出（5分）
4. 商品DBから候補商品を検索（10分）
5. AI提案資料生成でたたき台を自動生成（30分）
6. 営業担当者が微修正（30分）
7. 上長レビュー・修正（30分）
**合計: 2.3時間（49%削減）**

**関係者・役割**:
- 営業担当者: 提案資料作成の実施責任者
- 上長（営業マネージャー）: レビュー・承認
- 営業企画: ナレッジ登録、FAQ管理

**入力情報・出力情報**:
- 入力: 顧客情報（CRM）、過去提案資料、市況レポート、商品情報
- 出力: 提案資料（PowerPoint）

**業務ルール・判断ロジック**:
- 顧客の年齢・資産規模・リスク許容度に応じた商品フィルタリング
- コンプライアンス制約の遵守（適合性の原則、説明義務等）
- 分散投資の推奨（集中投資回避）

1. CRMで顧客情報確認（10分）

## 7.2 機能要件詳細

### F-001: 統合検索機能

**機能ID・機能名**: F-001 統合検索機能

**概要／目的**:
複数のデータソース（CRM、商品DB、市況レポートDB、社内規程DB、過去提案資料、FAQ DB、市場ニュース）を横断検索し、関連文書を抽出する。従来30〜60分かかっていた情報検索を10分以内に短縮する。

**前提条件・トリガー**:
- ユーザーがログイン済み
- 検索対象データソースが事前にインデックス化済み
- トリガー: ユーザーが検索クエリを入力

**入力（項目・形式・取得元）**:

| 項目 | 型 | 必須/任意 | 取得元 | 説明 |
|------|------|---------|-------|------|
| query | string | 必須 | ユーザー入力 | 検索キーワードまたは自然言語クエリ（例: "60代富裕層向けポートフォリオ提案"） |
| data_sources | array[string] | 任意 | ユーザー選択 | 検索対象データソース（デフォルト: 全て） |
| date_from | date | 任意 | ユーザー入力 | 検索対象期間の開始日 |
| date_to | date | 任意 | ユーザー入力 | 検索対象期間の終了日 |
| limit | integer | 任意 | システムデフォルト | 検索結果の最大件数（デフォルト: 20件） |

**出力（項目・形式・出力先）**:

| 項目 | 型 | 説明 |
|------|------|------|
| results | array[object] | 検索結果リスト |
| results[].id | string | 文書ID |
| results[].title | string | 文書タイトル |
| results[].summary | string | 文書要約（200文字程度） |
| results[].source | string | データソース名 |
| results[].score | float | 関連度スコア（0.0〜1.0） |
| results[].url | string | 文書へのリンク |
| total_count | integer | 検索結果総件数 |
| elapsed_time | float | 検索処理時間（秒） |

**API仕様**:

```
POST /api/v1/search
Content-Type: application/json

Request:
```

## 7.3 AIエージェント／ワークフロー要件

### AIエージェント要件

本プロジェクトでは、3種類のAIエージェントを実装します：

#### 1. 統合検索エージェント

**役割**: ユーザーの検索意図を理解し、最適なデータソースから関連文書を抽出

**利用者**: 営業担当者、営業企画メンバー

**典型的な対話パターン**:
```
ユーザー: 「60代富裕層向けの提案事例を探して」
エージェント: 「60代富裕層向けの過去提案を検索します。資産規模や商品種別の条件はありますか?」
ユーザー: 「資産5,000万円以上、配当株中心」
エージェント: 「検索結果: 15件の関連提案が見つかりました。最も関連度の高い5件を表示します」
```

**使用技術**: Azure OpenAI Service（GPT-4o）、Azure AI Search

**制約**:
- 検索クエリは最大500文字まで
- 検索結果は最大100件まで（デフォルト20件）
- レスポンスタイム: 3秒以内

#### 2. 要約エージェント

**役割**: 市況レポート等の文書を要約し、営業向けに要点を抽出

**利用者**: 営業担当者（特に若手）

**典型的な対話パターン**:
```
ユーザー: 「最新の市況レポートを要約して」
エージェント: 「2026年1月の市況レポートを要約します。重点トピックはありますか?」
ユーザー: 「金利動向と株価見通し」
エージェント: 「要約完了。金利は上昇懸念、株価は横ばい見通しです。詳細は以下の通りです...」
```

**使用技術**: Azure OpenAI Service（GPT-4o）、Azure AI Document Intelligence

**制約**:
- 要約対象文書は最大10MB（PDF換算で約100ページ）まで
- 要約文は最大2,000文字まで
- レスポンスタイム: 10秒以内

#### 3. 提案資料生成エージェント

**役割**: 過去提案事例と最新市況を組み合わせて提案資料のたたき台を生成

**利用者**: 営業担当者

**典型的な対話パターン**:
```
ユーザー: 「顧客Aさん向けのポートフォリオ提案を作成して」
エージェント: 「顧客Aさんの情報をCRMから取得します。過去の類似提案を参考にしますか?」
ユーザー: 「はい、60代富裕層向けの提案事例を参考にして」
エージェント: 「提案資料を生成中です...完了しました。15スライドの提案資料を作成しました」
```

**使用技術**: Azure OpenAI Service（GPT-4o）、Azure AI Document Intelligence、PowerPoint生成ライブラリ

**制約**:
- 生成されるスライドは最大30枚まで
- レスポンスタイム: 30秒以内

### ワークフロー要件

#### ワークフローステップ構成

AIエージェントが実行するワークフローは、以下の5つのステップで構成されます：

```
1. 情報収集
   ↓
2. 分析
   ↓
3. 生成
   ↓
4. 検証
   ↓
5. 出力
```

**1. 情報収集**:
- ユーザーの入力情報（検索クエリ、顧客情報等）を取得
- 関連データソースから必要な情報を収集

**2. 分析**:
- 収集した情報を分析し、ユーザーの意図を理解
- 必要な処理ステップを決定

**3. 生成**:
- AIエージェントが文書・要約・提案資料を生成
- プロンプトエンジニアリングにより品質を最適化

**4. 検証**:
- 生成された内容の妥当性を検証
- ガードレール（禁止ワード、コンプライアンス）をチェック

**5. 出力**:
- 検証済みの結果をユーザーに返却
- 履歴を保存

#### 再実行・再生成・フィードバック反映の要件

**再実行要件**:
- ユーザーは検索・要約・生成を最大5回まで再実行可能
- 再実行時は前回の結果を参考に改善
- 再実行履歴を保存し、ユーザーが過去の結果を参照可能（最大10件）

**再生成要件**:
- 提案資料生成後、ユーザーは以下の操作が可能:
  - スライド単位での再生成（例: 「スライド3を再生成」）
  - 書き直し指示（例: 「もっと簡潔に」「数値を追加」）
  - 代替案生成（例: 「別の商品構成で提案」）

**フィードバック反映要件**:
- ユーザーは生成結果に対してフィードバックを提供可能:
  - 良い/悪いの評価（👍/👎）
  - コメント入力（自由記述）
- フィードバックはモデル改善のために蓄積
- Phase 2以降でファインチューニングに活用

## 13.1 テスト観点

### シナリオテスト

Phase 1（PoC）では、3つのユースケースについてシナリオテストを実施します：

#### UC-01: 富裕層向けポートフォリオ提案（8ステップ）

1. 顧客情報（60代、資産5,000万円）をCRMから確認
2. AI統合検索で類似顧客の過去提案を検索
3. 検索結果を確認し、関連度の高い提案を選択
4. AI要約で市況レポートの要点を抽出
5. 商品DBから候補商品を検索
6. AI提案資料生成でたたき台を作成
7. 生成された提案資料を確認・微修正
8. 上長レビューを依頼

#### UC-02: NISA活用支援（8ステップ）

1. 顧客情報（30代、資産300万円）をCRMから確認
2. AI統合検索でNISA関連資料と若年層向け過去提案を検索
3. 検索結果を確認し、関連資料を選択
4. AI要約で成長株関連市況情報を抽出
5. 商品DBから候補商品を検索
6. AI提案資料生成でたたき台を作成
7. 生成された提案資料を確認・微修正
8. 上長レビューを依頼

#### UC-03: 市況急変時の顧客フォロー（8ステップ）

1. 顧客の保有商品をCRMから確認
2. AI統合検索で市況急変関連レポート・過去事例・FAQを検索
3. 検索結果を確認し、関連情報を選択
4. AI要約で市況解説・今後の見通しを生成
5. AI提案資料生成でフォロー資料のたたき台を作成
6. 生成されたフォロー資料を確認・顧客個別情報を追記
7. 上長レビューを依頼

### UAT確認観点

ユーザー受入テスト（UAT）では、以下の観点で確認を実施します：

#### 機能性（6項目）

1. 統合検索機能が正しく動作するか（複数データソース横断検索）
2. 検索結果の関連度が適切か（期待する結果が上位に表示される）
3. 市況レポート要約機能が正しく動作するか（要点が適切に抽出される）
4. 提案資料生成機能が正しく動作するか（たたき台が適切に生成される）
5. 生成された提案資料の品質が十分か（修正箇所が少ない）
6. 履歴管理機能が正しく動作するか（過去の検索・生成履歴を参照可能）

#### 使いやすさ（4項目）

1. 画面操作が直感的か（迷わず操作できる）
2. 検索クエリの入力が簡単か（自然言語で入力可能）
3. 生成結果の確認が容易か（プレビュー機能が充実）
4. エラーメッセージが分かりやすいか（対処方法が明示される）

#### 性能（4項目）

1. 検索レスポンスタイムが3秒以内か
2. 要約レスポンスタイムが10秒以内か
3. 提案資料生成レスポンスタイムが30秒以内か
4. 同時接続20名でも性能劣化がないか

#### セキュリティ（4項目）

1. Azure AD SSOで正しく認証されるか
2. ロール別のアクセス制御が正しく機能するか（権限外の機能にアクセスできない）
3. 監査ログが正しく記録されるか（すべての操作が記録される）
4. データマスキングが適切に実施されているか（個人情報が保護される）
