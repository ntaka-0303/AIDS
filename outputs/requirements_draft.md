# **3. 背景・目的**

## 3.1 背景

リテール営業部門の提案業務において、以下の業務課題が確認されています（提案書 2章、プロジェクト憲章参照）。

| 課題ID | 課題内容 | 現状の影響 | 根拠 |
|--------|----------|-----------|------|
| ISS-001 | 情報検索が複数システム横断で非効率 | 1案件あたり30-60分の検索時間、平均40分 | 初回ヒアリング |
| ISS-002 | 過去提案が支店ローカルに埋もれている | ナレッジ活用不可、類似提案が見つからない | 初回ヒアリング |
| ISS-003 | 市況レポートの量が多く若手が要点を掴めない | 市況理解の属人化、営業スキルの格差拡大 | 初回ヒアリング |
| ISS-004 | 資料作成が毎回スクラッチで時間がかかる | 1-2時間/提案の作成時間、平均1時間 | 初回ヒアリング |

これらの課題により、提案業務の生産性が低下し、若手社員の負担増加・提案品質のばらつきが発生しています。

## 3.2 システム化（AI活用）の目的

AI Workforceを活用することで、以下を実現します：

1. **生産性向上**: 検索・市況理解・資料作成の時間削減
2. **品質向上**: 若手支援による市況理解・資料品質の底上げ
3. **ナレッジ活用促進**: 調査部レポート・商品資料・FAQの統合検索
4. **現場の受容性確保**: 抵抗が少なく、現場が「使いたい」と思う機能の提供

Phase1 PoCでは、効果が実感しやすい領域に絞って段階的に導入し、確実な成果創出を目指します（DEC-004: 段階的導入方針）。

## 5.1 業務全体像

### 対象業務プロセス（DEC-002）

リテール営業部門の提案業務は以下の6つのプロセスで構成されます。

```
1. 顧客ヒアリング
   ↓
2. 情報検索 ← Phase1対象（REQ-001）
   ↓
3. 市況整理 ← Phase1対象（REQ-002）
   ↓
4. 商品選定
   ↓
5. 資料作成 ← Phase1対象（REQ-003）
   ↓
6. 上長レビュー
```

※ 実際には2-4の間で行き来が発生し、手戻りが多い状況です。

### Phase1で解決する課題

| プロセス | 現状の課題 | AI Workforceによる解決 |
|---------|-----------|----------------------|
| 情報検索 | 複数システム横断で30-60分/案件 | 統合検索+要点抽出で検索時間を20分に短縮 |
| 市況整理 | レポートが多く若手が要点を掴めない | 営業向け要約で市況理解度を向上（平均4.0/5.0以上） |
| 資料作成 | 毎回スクラッチで1-2時間/案件 | テンプレートベースのたたき台生成で作成時間を30分に短縮 |

## 6.2 業務要件詳細

### UC-01: ナレッジ統合検索

**目的・背景**:
営業担当が提案準備のために複数システム（調査部レポート・商品資料・FAQ等）を横断して情報検索する際、1案件あたり30-60分の時間を要している。統合検索と要点抽出により、検索時間を20分に短縮する。

**業務フロー概要**:

| フロー | Before（現状） | After（AI Workforce導入後） |
|--------|---------------|--------------------------|
| 1. 検索開始 | 複数システムを個別にログイン・検索 | AI Workforceで統合検索クエリを入力 |
| 2. 情報収集 | 各システムから資料をダウンロード・閲覧 | 検索結果が統合表示、要点が抽出される |
| 3. 要点把握 | 手動で資料を読み込み、要点をメモ | AIが要点を抽出・サマリを提示 |
| 4. 検索完了 | 30-60分の時間を要する | 20分で完了（目標） |

**関係者・役割**:
- **営業担当**: 検索実行・要点確認
- **DX推進部**: データソースの定期更新

**入力情報**:
- 検索クエリ（キーワード、文章形式の質問）
- 検索対象データソース（調査部レポート、商品資料、FAQ）

**出力情報**:
- 検索結果一覧（関連度順）
- 各結果の要点抽出サマリ
- 引用元ドキュメントへのリンク

**業務ルール・判断ロジック**:
- 検索精度80%以上を確保（DEC-022）
- 引用元を明示し、幻覚（ハルシネーション）を防止
- 検索対象はPhase1では調査部レポート・商品資料・FAQに限定（DEC-007）

### UC-02: 市況レポート要約

**目的・背景**:
調査部が発行する市況レポートは情報量が多く、若手営業担当が要点を掴めない。営業向けに要約し、顧客への説明に活用できる形に整理する。

**業務フロー概要**:

| フロー | Before（現状） | After（AI Workforce導入後） |
|--------|---------------|--------------------------|
| 1. レポート入手 | 調査部から市況レポートを受領 | AI Workforceが最新レポートを自動取得 |
| 2. 要点把握 | 若手が20-40分かけて読み込むが要点を掴めない | AIが営業向けに要約・示唆を提示 |
| 3. レビュー | なし | 調査部 田中課長が2次レビュー（DEC-017） |
| 4. 顧客説明 | 専門用語が多く説明しにくい | 営業向け表現で説明可能 |

**関係者・役割**:
- **営業担当**: 要約を確認・1次レビュー
- **調査部 田中課長**: 2次レビュー（専門的観点、コンプライアンス）
- **DX推進部**: 市況レポートの定期アップロード

**入力情報**:
- 市況レポート（PDF形式、直近3ヶ月分、約12レポート）
- 要約の観点（営業向け、顧客説明用等）

**出力情報**:
- 営業向け要約サマリ
  - エグゼクティブサマリ（3-5行）
  - 市場動向の要点（箇条書き）
  - 営業への示唆（顧客への説明ポイント）
- 引用元レポートへのリンク

**業務ルール・判断ロジック**:
- PoC期間中は調査部のレビューを必須とする（DEC-008）
- レビューフロー: AI生成 → 1次レビュー（営業担当） → 2次レビュー（調査部 田中課長） → 承認・公開（DEC-017）
- レビュー期限: 生成から48時間以内
- レビュー観点: 要約の正確性、営業向け表現の適切性、機密情報除外、コンプライアンス
- 要約精度: アンケート平均4.0/5.0以上（DEC-012）
- 誤情報生成: 5%以下（DEC-022）

### UC-03: 提案資料たたき台生成

**目的・背景**:
提案書を毎回スクラッチで作成しており、1-2時間/案件の時間を要している。既存テンプレートに沿ったたたき台を自動生成し、作成時間を30分に短縮する。

**業務フロー概要**:

| フロー | Before（現状） | After（AI Workforce導入後） |
|--------|---------------|--------------------------|
| 1. テンプレート選択 | PowerPointテンプレートを開く | AI Workforceでテンプレート種別を選択 |
| 2. 内容入力 | 手動で顧客名・商品名等を入力 | 入力情報を指定（顧客名、商品名、課題等） |
| 3. 文章作成 | スクラッチで各セクションを作成（1-2時間） | AIが各セクションのテキストを生成（2分以内） |
| 4. レビュー・修正 | 上長レビュー、修正 | たたき台をベースに修正（作業時間30分目標） |

**関係者・役割**:
- **営業担当**: テンプレート選択・入力情報指定・修正
- **中村・高橋（レビュー担当）**: 生成物の品質チェック

**入力情報**:
- テンプレート種別（商品提案、ソリューション提案）
- 顧客名、商品名、課題、市況情報等
- （オプション）参考にする過去提案書

**出力情報**:
- 提案書たたき台（PowerPoint形式またはテキスト形式）
  - 表紙、背景、商品概要、メリット、リスク、次のステップ（商品提案の場合）
  - 表紙、課題整理、ソリューション概要、効果試算、導入ステップ（ソリューション提案の場合）

**業務ルール・判断ロジック**:
- Phase1では既存テンプレートのみ対応（DEC-009）
- テンプレート詳細仕様（DEC-016）:
  - **商品提案テンプレート**（最優先、10-15スライド、背景・商品概要・メリット・リスクをAI生成）
  - **ソリューション提案テンプレート**（15-20スライド、課題整理・ソリューション概要をAI生成）
- テンプレートがない領域はテキスト生成のみ
- レイアウト変更や新テンプレート作成はPhase2以降
- 作成時間: 1時間 → 30分に短縮（目標、DEC-012）
- 品質スコア: レビュー指摘件数を20%削減（目標、DEC-012）

## 7.2 機能要件詳細

### F-001: 統合検索機能

**機能ID・機能名**: F-001 / 統合検索機能

**概要／目的**:
複数データソース（調査部レポート・商品資料・FAQ）を横断して統合検索し、関連度の高い情報を抽出する。

**前提条件・トリガー**:
- ユーザーがAI Workforceにログイン済み
- 検索対象データがセキュア領域にアップロード済み

**入力**:
- 検索クエリ（キーワードまたは文章形式の質問）
  - 例: 「米国金利動向」「リスク許容度が低い顧客向けの商品」
- 検索対象データソース（オプション指定可能）
  - デフォルト: 全データソース
  - 個別指定: 調査部レポートのみ、商品資料のみ等

**出力**:
- 検索結果一覧（関連度順、最大20件）
  - ドキュメント名
  - 関連度スコア
  - マッチした箇所のハイライト表示
  - 引用元ドキュメントへのリンク

**画面・帳票・API 等の振る舞い**:
- Web UI: 検索ボックスにクエリを入力、Enterキーまたは検索ボタンで実行
- 検索結果はリスト形式で表示、各結果をクリックすると詳細表示
- 応答時間: 5秒以内（目標）

**正常系・例外系の振る舞い**:
- **正常系**: 検索クエリに対して関連するドキュメントが見つかる場合、結果を表示
- **例外系1**: 検索結果が0件の場合、「該当する情報が見つかりませんでした。別のキーワードで検索してください。」と表示
- **例外系2**: システムエラーの場合、「検索に失敗しました。しばらくしてから再試行してください。」と表示

**受入条件**:
- [ ] 調査部レポート・商品資料・FAQを横断して検索できる
- [ ] 検索精度80%以上（サンプル20件で評価、DEC-022）
- [ ] 応答時間5秒以内
- [ ] 検索結果に引用元が明示されている

### F-002: 要点抽出機能

**機能ID・機能名**: F-002 / 要点抽出機能

**概要／目的**:

## 7.3 AIエージェント／ワークフロー要件

### エージェントの役割・対話パターン

**検索エージェント**:
- 役割: ユーザーの検索クエリを理解し、適切なドキュメントを検索・要点抽出
- 利用者: PoC参加メンバー5名（営業担当）
- 典型的な対話パターン:
  - ユーザー: 「米国金利動向について教えて」
  - エージェント: 調査部レポートを検索し、要点を抽出して提示
  - ユーザー: 「もっと詳しく教えて」
  - エージェント: 該当するレポートの詳細セクションを提示

**要約エージェント**:
- 役割: 市況レポートから営業向けの要約サマリを生成
- 利用者: PoC参加メンバー5名（営業担当）
- 典型的な対話パターン:
  - ユーザー: 市況レポートを選択し「要約生成」を実行
  - エージェント: エグゼクティブサマリ、市場動向の要点、営業への示唆を生成
  - ユーザー: レビュー担当者にレビュー依頼
  - エージェント: レビューフローを管理、承認後に公開

**テンプレート生成エージェント**:
- 役割: 既存テンプレートに沿った提案書のたたき台を生成
- 利用者: PoC参加メンバー5名（営業担当）
- 典型的な対話パターン:
  - ユーザー: テンプレート種別・入力情報を指定
  - エージェント: 各セクションのテキストを生成（背景、商品概要、メリット等）
  - ユーザー: たたき台をベースに修正・編集

### ワークフローのステップ構成

**情報検索ワークフロー**:
1. **入力**: ユーザーが検索クエリを入力
2. **検索**: 統合検索を実行（Azure AI Search）
3. **要点抽出**: RAGで要点を抽出（Azure OpenAI）
4. **検証**: 引用元を明示、幻覚防止
5. **出力**: 検索結果と要点サマリを表示

**市況要約ワークフロー**:
1. **入力**: ユーザーが市況レポートを選択
2. **要約生成**: 営業向け要約を生成（Azure OpenAI）
3. **1次レビュー**: 営業担当が正確性を確認
4. **2次レビュー**: 調査部 田中課長が専門的観点・コンプライアンスを確認
5. **承認・公開**: レビュー完了後、要約を公開

**提案資料生成ワークフロー**:
1. **入力**: ユーザーがテンプレート種別・入力情報を指定
2. **テンプレート読込**: 既存テンプレート構造を読み込み
3. **テキスト生成**: 各セクションのテキストを生成（Azure OpenAI）
4. **検証**: 生成内容の整合性チェック
5. **出力**: たたき台を表示

### 再実行・再生成・フィードバック反映の要件

**再実行・再生成**:
- ユーザーは生成結果に満足しない場合、パラメータを調整して再生成可能
- 再生成回数: 制限なし（ただし、過度な利用は利用状況ログで監視）

**フィードバック反映**:
- 各生成結果に対して、ユーザーが5段階評価とコメントを入力可能
- フィードバックはシステムログに記録され、品質改善に活用
- 週次ミーティングでフィードバックを集約し、プロンプト改善・モデル調整を実施

# **9. インターフェース要件**

## 9.1 外部システム連携

### Phase1の方針（DEC-023）

**Phase1では外部システム連携を実施しない方針**。理由は以下の通り。

1. PoCの目的は機能評価であり、システム連携は本質的評価対象ではない
2. 既存システム連携には社内セキュリティ審査（1-2ヶ月）が必要でPoC期間に間に合わない
3. まずファイルベースでの価値検証を優先し、連携は効果確認後に検討

### データ提供方式

| 項目 | 方式 |

# **14. リスク・課題**

Phase1（PoC）で想定されるリスクと対策を以下に示します（プロジェクト計画書 12章参照）。

## 14.1 主要リスク

### RSK-001: 現場の抵抗によるPoC不活性化

**リスク内容**:
一気に全業務をAI化しようとすると現場の抵抗が大きくなり、PoCが形骸化する可能性がある。

**影響度**: 高
**発生確率**: 中
**リスクスコア**: 6

**早期シグナル**:
- 現場からのフィードバックが得られない
- PoC参加者の参加率低下（利用率80%を下回る）
- 「使いにくい」「業務に合わない」という声が増加

**予防策**:
1. 現場が改善を実感しやすい領域に絞ってPoCを実施（情報検索を最優先）
2. 現場の抵抗が少ないテーマを優先選定（既存テンプレートのみ対応）
3. 現場が「使ってみたい」と思うテーマを中心に進める
4. 段階的導入で成功体験を積み重ねる（Phase1→Phase2）
5. 週次ミーティングで継続的にフィードバック収集・改善

**対応策（早期シグナル検知時）**:
1. PoC対象領域の再選定（優先順位の見直し）
2. 現場ヒアリングの追加実施（個別面談）
3. スコープの縮小（情報検索のみに集中）
4. 利用方法の再トレーニング

**責任者**: LayerX（高松）
