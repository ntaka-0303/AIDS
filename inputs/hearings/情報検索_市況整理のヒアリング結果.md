# 📘 **情報検索 & 市況整理：ヒアリング結果まとめ（AI読み込み最適化版）**

本メモは、

* 現場営業（山口）
* 情シス（山根）
* 調査部（杉本代理）
  からの回答を統合し、**As-Is → Pain → To-Be → PoCへの示唆** の流れで整理しています。

---

# 🟥 **1. 業務の発生タイミング・頻度（共通理解）**

## ● 情報検索

* 発生タイミング：

  * 顧客訪問前日
  * 当日朝
  * 提案書作成途中
* 件数：**週10〜15件**（個人営業）
* 繁忙期は **1.5〜2倍**

## ● 市況整理

* 発生タイミング：重要提案の前
* 件数：**週3〜5件**
* 市況簡易チェックは毎朝実施

---

# 🟥 **2. 情報検索：As-Is（現状）**

## ● よく使う検索先

* 調査部レポート（SharePoint）
* 商品企画部フォルダ（投信・債券・仕組債）
* 支店NASの提案書フォルダ
* 社内FAQ（ポータル）
* 規程管理システム

→ **10以上のシステム / フォルダを横断**する必要あり。

## ● 調査対象

* 市況の補足
* 類似提案事例
* 商品比較
* リスク説明
* 顧客興味テーマ（米株・為替）

## ● 所要時間

* 1案件あたり **30〜60分**

## ● “諦める”ケース

* 類似提案が見つからない
* 情報量が多く、精読する時間がない
* 古い資料と新しい資料が混在
* 市況レポートが膨大すぎる

## ● 情報過多での困りごと

* マクロレポート（20〜40ページ）
* 債券市場レポート（専門用語が多い）
* 米株個別レポート

---

# 🟥 **3. 情報検索：Pain（課題）**

1. **情報がサイロ化**していて横断検索できない
2. **最新資料の所在が不明確**
3. 過去提案は支店NASに散在し、検索が困難
4. PDFやPPTが多く、手作業で読み込むしかない
5. 情報が多すぎて、営業が消化しきれない
6. “調べて終わり” になり、提案につながらない

→ **時間負荷・心理負荷が最も大きい領域**

---

# 🟥 **4. 市況整理：As-Is（現状）**

## ● 市況レポートの読解状況

* 毎朝の簡易版チェック
* 重要案件では深掘り（週1〜2回）

## ● 手順

1. 調査部レポートを読む
2. キーワード抜き出し
3. 顧客向けに言い換える
4. PPTにまとめる（1〜2ページ）

## ● 所要時間

* **20〜40分／件**

## ● 若手の苦手ポイント

* 重要情報の取捨選択
* 市況 ⇄ 商品 を結びつけること
* 専門用語の理解
* 市況ストーリーの構築

## ● “説明できない” と感じた場面

* 金利動向の背景
* 為替の変動理由
* 米株調整局面の説明
* マクロ要因が複雑なとき

---

# 🟥 **5. 市況整理：Pain（課題）**

1. レポートの情報量が多すぎて読む時間がない
2. 若手は専門用語を理解できず、**顧客向けの説明に落とし込めない**
3. 調査部の意図を誤解した説明をしてしまうリスク
4. 市況→提案への「つながり」を作れない
5. レポートが活用されない（読まれない）

→ **営業スキルの属人性が最も顕著な領域**

---

# 🟦 **6. 情報検索：To-Be（理想状態）**

1. **質問すれば1アクションで必要な情報が出る**

   * 市況
   * 商品情報
   * 過去提案
   * FAQ
   * 規程
     を横断。

2. **粒度（要点 / 詳細）を切り替え可能**

3. 類似提案の自動検索

4. 過去の説明文を再利用可能（整形した形で提示）

5. 古い資料か新しい資料かをAIが判断

---

# 🟪 **7. 市況整理：To-Be（理想状態）**

1. **営業向け要約（1〜2分で読める）** が自動生成
2. 顧客に合わせた説明文をAIが生成
3. 市況 → 提案につながる“示唆”を提示
4. 調査部レビュー済みの表現を維持
5. 若手でも自信を持って説明できる状態

---

# 🟥 **8. 情シス視点：データ・権限・セキュリティ**

## ● データ形式

* PDF, PPT, Excel, HTML（混在）

## ● 権限

* CRMメモは不可
* 支店NASは権限複雑
* PoCは **AI Workforceセキュアストレージのみ**

## ● セキュリティ

* 未マスクデータの外部SaaSアップロード禁止
* AI検索ログ・回答ログの保全必須（180日以上）
* 本番ではAD連携・二要素認証が必要

---

# 🟥 **9. 調査部視点：市況レポートの特性・期待・懸念**

## ● 市況レポートの構造

* PDF中心
* 5〜20ページ
* 市況 → 背景 → 見通し → リスク → 投資アイデア

## ● 営業への期待

* 市況ストーリーを正しく理解し説明してほしい
* 1〜2分で要点を把握できる状態が理想

## ● 懸念

* 表現のぶれ
* 過度に断定的な内容
* 特定銘柄推奨に見える記述
* 公式見解との齟齬

## ● AIへの期待

* 要点抽出
* 営業向け説明文の生成
* 調査部への問い合わせ削減

---

# 🟧 **10. PoC設計への示唆（AI活用ポイント）**

以下の領域が **PoCで価値が出やすい** と判断：

### **● 情報検索**

* システム横断検索
* PDF/PPT要点抽出
* 類似提案レコメンド
* 最新資料優先の判断

### **● 市況整理**

* 営業向けの自然言語サマリー
* 顧客属性に合わせた説明生成
* 「市況→商品のつながり」提示
* 調査部レビュー前提で品質担保

---

# 🟦 **11. 営業部共通のストレス（AI導入の価値が大きい領域）**

1. とにかく検索時間が長い
2. 市況を読み込む時間がない
3. 何が重要か分からない
4. 説明に自信が持てない
5. 情報の整理と構造化が苦手
6. 手戻り（修正依頼）が多い

→ **このストレスをどれだけ軽減できるかがPoC成功の鍵**

---

# 🟩 **12. 営業部のPoC受容性**

* AIにかけられる時間は **1案件5分以内**
* 操作が複雑・遅い・誤回答が続くと定着しない
* フィードバックは週1回・短時間なら協力可

---

# 🟦 **まとめ**

**情報検索**
→ 時間負荷が最も高く、サイロ化・資料散在・検索疲弊が顕著
→ 横断検索＋要点抽出のAI適性が非常に高い

**市況整理**
→ 若手の苦手領域、属人性が最大
→ 営業向け要約と“市況→提案”のストーリー生成が価値大
→ 調査部レビュー前提でPoC可能

**情シス・調査部の制約もクリア**
→ 個人情報除外
→ 調査部レビュー前提
→ AI Workforceセキュアストレージ利用

→ **PoC対象として十分に適性がある**
