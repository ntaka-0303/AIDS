# Hearing Add Skill - ヒアリングメモ登録

## 概要
新しいヒアリングメモを`inputs/hearings/`に登録する。
以下の2つのモードをサポート:
- **内容貼付モード**: チャットにMarkdown内容を直接貼り付け
- **ファイル指定モード**: 既存ファイルのパスを指定（ドラッグ&ドロップ対応）

## 実行トリガー

### 内容貼付モード
- 「ヒアリングを追加」
- 「ヒアリングメモを登録」
- 「hearing add」
- 「hearing-add」

### ファイル指定モード
- 「[ファイルパス] をヒアリングとして追加」
- 「このファイルをヒアリングに登録: [ファイルパス]」
- ドラッグ&ドロップ後に「これをヒアリングとして追加」
- 「ヒアリングファイルを登録」

## 実行ステップ

### Step 1: モード判定
ユーザー入力からモードを判定:
- ファイルパス（絶対パスまたは相対パス）が含まれる → **ファイル指定モード**
- Markdown内容が含まれる → **内容貼付モード（直接保存）**
- それ以外 → **内容貼付モード（メタデータ質問から開始）**

### Step 2: メタデータ収集

**収集する情報:**
| 項目 | 必須 | 自動推測 | 説明 |
|-----|------|---------|------|
| date | Yes | ファイル名/内容から | ヒアリング実施日 (YYYY-MM-DD) |
| title | Yes | 内容から | ヒアリングタイトル |
| topic | Yes | titleから | ファイル名用トピック（日本語可、スペースは使用不可） |
| participants | No | 内容から | 参加者リスト |
| summary | No | 内容から | 概要（1-2文） |

**質問フロー（内容貼付モード）:**
1. まずメタデータを質問
2. ユーザーが回答
3. 「ヒアリング内容を貼り付けてください」と依頼
4. Markdown内容を受け取り保存

**質問フロー（ファイル指定モード）:**
1. ファイル内容を読み取り
2. 内容からメタデータを推測して提案
3. ユーザーが確認または修正
4. 新しいファイル名でコピー保存

**質問例:**
```
以下の情報を教えてください:
- ヒアリング実施日（例: 2026-01-20）:
- タイトル（例: 要件詳細ヒアリング）:
- 参加者（カンマ区切り、省略可）:
```

### Step 3: ファイル名生成

**命名規則:**
```
{YYYYMMDD}_{topic}.md

例:
- 20260125_初回ヒアリング.md
- 20260130_セキュリティ要件確認.md
```

**注意事項:**
- 日付は`YYYYMMDD`形式（ハイフンなし）
- topicは日本語可、ただし空白や特殊文字（`/`, `\`, `:`, `*`, `?`, `"`, `<`, `>`, `|`）は使用不可
- 空白はアンダースコア`_`に変換

**重複チェック:**
同名ファイルが存在する場合は警告し、サフィックスを追加:
```
20260125_初回ヒアリング_2.md
```

### Step 4: ファイル保存

**内容貼付モードの場合:**
1. ユーザーに「ヒアリング内容を貼り付けてください」と依頼
2. 貼り付けられた内容をそのまま保存
3. 保存先: `inputs/hearings/{YYYYMMDD}_{topic}.md`

**ファイル指定モードの場合:**
1. 指定されたファイルの内容を読み取り
2. 新しいファイル名で`inputs/hearings/`にコピー
3. 元のファイルは変更しない

### Step 5: _index.yaml更新

**ID採番:**
- `inputs/hearings/_index.yaml`を読み込む
- 既存の最大`HEAR-XXX`番号を特定
- 次の番号を採番（例: HEAR-003 → HEAR-004）

**追加エントリ形式:**
```yaml
- id: "HEAR-004"
  title: "{title}"
  date: "{YYYY-MM-DD}"
  participants:
    - "{participant1}"
    - "{participant2}"
  summary: "{summary}"
  add_date: "{今日の日付 YYYY-MM-DD}"
  processed: "No"
```

**更新方法:**
- 既存の`hearings:`配列の末尾に新規エントリを追加
- YAMLフォーマットを維持

### Step 6: 完了報告

**出力例:**
```
[Hearing Add完了]
- ファイル: inputs/hearings/20260125_セキュリティ要件確認.md
- 登録ID: HEAR-004
- タイトル: セキュリティ要件確認ヒアリング
- 実施日: 2026-01-25
- 参加者: 山田太郎, 佐藤花子
- 状態: 未処理（processed: No）

次のアクション:
→ 「intakeを実行」でヒアリング内容を取り込み、project_stateを更新できます
```

## エラー処理

| エラー | 対応 |
|-------|-----|
| ファイルパスが無効 | 「ファイルが見つかりません: {path}」と報告 |
| ファイル読み取り失敗 | エラー内容を報告、リトライ提案 |
| 必須情報が不足 | 再度質問して収集 |
| ファイル名重複 | サフィックス追加を提案（例: `_2`, `_3`） |
| 書き込み失敗 | エラー報告、リトライ提案 |
| 無効な日付形式 | 正しい形式（YYYY-MM-DD）を再入力依頼 |

## 注意事項

1. **エンコーディング**: UTF-8で保存
2. **改行コード**: LF統一（Windowsでも）
3. **ファイル名のトピック**: 日本語可、特殊文字・空白は避ける
4. **自動Intake**: 登録後、自動でIntakeは実行しない（ユーザー判断）
5. **元ファイル**: ファイル指定モードでも元のファイルは削除・変更しない

## 他スキルとの連携

| スキル | 連携内容 |
|--------|---------|
| **Intake** | ヒアリング追加後、「intakeを実行」で内容を処理 |
| **ProjectMgmt** | Intake後の状態管理（課題・リスク等の更新） |

**フロー例:**
1. `hearing-add` → ヒアリングファイルを登録（processed: No）
2. `intake` → ヒアリング内容を処理、project_state更新（processed: Yes）
3. `project-management` → 課題・リスク等の状態更新

## UX例

### 例1: 内容貼付モード

```
User: ヒアリングを追加

Agent: 以下の情報を教えてください:
       - ヒアリング実施日（例: 2026-01-20）:
       - タイトル:
       - 参加者（カンマ区切り、省略可）:

User: 2026-01-25, セキュリティ要件確認, 山田太郎, 佐藤花子

Agent: ヒアリング内容をMarkdown形式で貼り付けてください。

User: # セキュリティ要件確認ヒアリング
      ## 概要
      ...（Markdown内容）

Agent: [Hearing Add完了]
       - ファイル: inputs/hearings/20260125_セキュリティ要件確認.md
       - 登録ID: HEAR-004
       - タイトル: セキュリティ要件確認
       - 実施日: 2026-01-25
       - 参加者: 山田太郎, 佐藤花子
       - 状態: 未処理（processed: No）

       → 「intakeを実行」で取り込みできます
```

```

User: OK

Agent: [Hearing Add完了]
       - ファイル: inputs/hearings/20260125_セキュリティ要件確認.md
       - 登録ID: HEAR-004
       ...
```
